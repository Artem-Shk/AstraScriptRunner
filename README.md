# script_runner (Linux)

Консольная утилита на Python для запуска bash-скриптов из указанной папки.
Рассчитана на Linux/POSIX.

## Возможности

- Рекурсивное или неглубокое сканирование папки.
- Поиск файлов с расширениями `.sh` / `.bash`.
- Пропуск файлов без права на выполнение (флаг `--force` отменяет проверку).
- Фильтр по имени/расширению, сортировка по имени, дате изменения или размеру.
- Последовательный или параллельный запуск (пул потоков).
- Передача аргументов каждому скрипту (после `--`).
- Сохранение stdout/stderr каждого скрипта в отдельный лог-файл.
- Обработка кодов возврата и таймаутов; ошибка одного скрипта не останавливает
  остальные.
- Режим `--dry-run`, подробный режим `-v`, конфигурация JSON/YAML.

## Требования (Linux)

- Python 3.8+ (`python3`).
- `bash` — обычно уже установлен; иначе:
  - Debian/Ubuntu: `sudo apt-get install -y bash`
  - Fedora/RHEL:   `sudo dnf install -y bash`
  - Arch:          `sudo pacman -S bash`
- Для YAML-конфига — необязательный пакет `PyYAML` (`pip install pyyaml`).

## Установка

```bash
# сделать файлы исполняемыми
chmod +x script_runner.py run.sh
chmod +x scripts/*.sh scripts/**/*.bash
```

## Быстрый старт

```bash
# Запустить все скрипты в ./scripts рекурсивно, последовательно
./script_runner.py ./scripts -r

# То же через удобную обёртку
./run.sh -r

# Только показать, что будет запущено (без выполнения)
./script_runner.py ./scripts -r --dry-run

# Параллельно, 4 воркера, фильтр по имени, сортировка по дате (новые первыми)
./script_runner.py ./scripts -m parallel -j 4 -f "deploy*" -s mtime --reverse

# Передать аргументы каждому скрипту (всё после --)
./script_runner.py ./scripts -- --env prod --verbose

# Запустить даже неисполняемые файлы и ограничить время каждого скрипта
./script_runner.py ./scripts --force --timeout 30

# Из конфигурационного файла (CLI перекрывает значения из файла)
./script_runner.py ./scripts -c config.example.json

# Не писать лог-файлы
./script_runner.py ./scripts --no-log
```

Код возврата: `0` — всё успешно, `1` — были падения, `2` — ошибка/скрипты не
найдены, `130` — прерывание с клавиатуры.

## Параметры командной строки

| Параметр | Описание |
| --- | --- |
| `directory` | Папка со скриптами (обязательный). |
| `-f, --filter PATTERN` | Фильтр: `.sh`, `deploy*`, `backup`. |
| `-m, --mode sequential\|parallel` | Режим запуска. |
| `-r, --recursive` | Сканировать подпапки. |
| `--force` | Запускать даже без права на выполнение. |
| `-s, --sort name\|mtime\|size` | Ключ сортировки. |
| `--reverse` | Обратный порядок сортировки. |
| `-j, --jobs N` | Число параллельных воркеров. |
| `--timeout SEC` | Таймаут на скрипт. |
| `-o, --output-dir DIR` | Каталог для логов (по умолчанию `./logs`). |
| `--no-log` | Не писать лог-файлы. |
| `--dry-run` | Только показать план. |
| `--no-continue-on-error` | Остановиться после первой ошибки. |
| `-v, --verbose` | Подробный вывод. |
| `-c, --config FILE` | JSON или YAML конфиг. |
| `-- ARGS...` | Аргументы, передаваемые каждому скрипту. |

## Конфигурационный файл

Значения из файла применяются, если соответствующий флаг не задан в командной
строке (приоритет: CLI > config > встроенные значения). Поддерживаемые ключи
совпадают с именами параметров: `directory`, `filter`, `mode`, `recursive`,
`force`, `sort`, `reverse`, `jobs`, `timeout`, `output_dir`, `dry_run`,
`verbose`, `log`, `continue_on_error`, `script_args`.

## Логика работы

1. **Разбор аргументов.** Всё после `--` сохраняется как аргументы скриптов.
   Флаги парсера по умолчанию `None`, чтобы отличить «не задано» от значения.
2. **Мержинг конфигурации.** `merge_config` собирает итоговые настройки:
   CLI → config → default.
3. **Поиск `bash`.** `find_bash` ищет `bash` в `$PATH` и в `/bin`, `/usr/bin`,
   `/usr/local/bin`; при отсутствии — понятная ошибка с командой установки.
4. **Обнаружение скриптов.** `iter_candidate_files` перебирает файлы (рекурсивно
   или нет), отбирает по расширению, `matches_filter` фильтрует по имени,
   `discover_scripts` отбрасывает неисполняемые (если нет `--force`) и сортирует.
5. **Dry-run.** Печатает план и завершается без запуска.
6. **Запуск.** `ScriptRunner._run_one` вызывает `subprocess.run([bash, script,
   *args])` (без `shell=True`), пишет структурированный лог, ловит таймаут и
   ошибки запуска, возвращая `RunResult`; исключения не прерывают пакет.
7. **Режим.** Последовательный цикл или `ThreadPoolExecutor` для параллельного.
8. **Итог.** `_summarize` логирует сводку и возвращает код возврата процесса.

## Безопасность к некорректному вводу

- Проверка существования и типа папки, режима, ключа сортировки, `jobs` и
  `timeout` до запуска.
- Все дочерние процессы получают путь и аргументы как элементы списка (без
  `shell=True`) — нет подстановки команд.
- Некорректный/отсутствующий конфиг даёт понятное сообщение и код возврата 2.
- Ошибки `stat`, записи логов и запуска обрабатываются по отдельности, не
  роняя весь пакет.
